# 🛡️ Security Log Analyzer — SOC Monitoring Dashboard

A professional, high-performance Security Operations Center (SOC) dashboard and automated log analysis system built in Python with Streamlit and Plotly. The application parses heterogeneous operating system and service authentication logs, normalizes events into a unified data structure, detects credential attacks (Brute-Force & Multiple-Account Spraying), stores alerts safely in SQLite, and visualizes security telemetry across interactive charts.

## 🚀 Project Overview

The **Security Log Analyzer** enables cybersecurity analysts to rapidly ingest, analyze, and investigate authentication logs across Windows, Linux, and multi-platform network systems. Designed with modern SOC aesthetics (Deep Navy `#0B1220`, Secondary Panels `#111C2E`, Neon Cyan `#22D3EE`, Cobalt Blue `#3B82F6`, Emerald Green `#22C55E`, Amber `#F59E0B`, and Crimson `#EF4444`), the platform offers instant threat visibility without external CDN or cloud dependencies.

---

## 🎯 Problem Statement

Security and event logs generated by operating systems (Windows Event Logs) and authentication daemons (`sshd`, PAM) contain critical evidence of cyber intrusions. However:
- **Massive Volume:** High volumes of raw logs overwhelm manual security audits.
- **Heterogeneous Formats:** Disparate structures (CSV, Syslog RFC, Windows Event Viewer plain text, Pipe-delimited) prevent unified querying.
- **Stealthy Attacks:** Slow brute-force and credential spraying attempts easily bypass basic threshold filters.
- **Tooling Gaps:** Enterprise SIEMs are complex and resource-heavy for localized triage, educational analysis, and forensic post-mortems.

---

## 🏆 Objectives

- **Automated Multi-Format Parsing:** Ingest and parse Windows CSV, Windows Event Log text, Kali SSH Syslog, and standard pipe-delimited auth logs.
- **Event Normalization:** Unify heterogeneous records into a consistent JSON/Python schema (Timestamp, Event Type, Username, Source IP, Port, Status, Event ID).
- **Rule-Based Threat Detection:** Detect repeated brute-force attacks (SEC-RUL-001) and multiple-account credential spraying (SEC-RUL-002).
- **Interactive SOC Telemetry:** Render 8 core SOC visualizations (KPI cards, Authentication Timeline, Severity Distribution, Attack Breakdown, Hostile Source IPs, Authentication Outcomes, Threat Risk Gauge, and Searchable Alert Tables).
- **Database Safety & Deduplication:** Safely persist alerts in SQLite with parameterized queries, preventing duplicate alert creation upon re-analysis.
- **Offline Reliability:** Operate 100% offline with zero remote CDN, external font, or live API dependencies.

## 🏗️ System Architecture & Pipeline

The system enforces a strict 7-stage linear analysis workflow:

```
┌─────────────────┐
│  UPLOAD LOGS    │ Drag-and-drop (.csv, .log, .txt)
└────────┬────────┘
         │
┌────────▼────────┐
│ VALIDATE FILE   │ Buffer validation, encoding detection, SQLite health
└────────┬────────┘
         │
┌────────▼────────┐
│ READ LOG ENTRIES│ Byte buffer inspection, encoding normalization
└────────┬────────┘
         │
┌────────▼────────┐
│ PARSE & NORMALIZE Dynamic signature detection, field extraction
└────────┬────────┘
         │
┌────────▼────────┐
│ CHECK ATTEMPTS  │ Group failed logins by IP address and target account
└────────┬────────┘
         │
┌────────▼────────┐
│ EVALUATE RULES  │ Brute-force (SEC-RUL-001) & Account Spraying (SEC-RUL-002)
└────────┬────────┘
         │
┌────────▼────────┐
│ PERSIST ALERTS  │ SQLite parameterized insertion with deduplication
└────────┬────────┘
         │
┌────────▼────────┐
│ RENDER SOC VIEWS│ KPI cards, Plotly charts, and export data
└─────────────────┘
```

## 📜 Supported Log Formats

| Format Name | Detection Signature | Key Fields Extracted |
|---|---|---|
| **Windows Security CSV** | Header containing `EventID`, `SourceIP`, `LogonType` | `EventID` (4624/4625), Timestamp, Username, Source IP, Source Port, Logon Type |
| **Windows Event Viewer Text** | Multi-line text blocks with `TimeCreated`, `Id :`, `Account Name` | Timestamp, Event ID, Target Username, Source Network Address |
| **Linux SSH Syslog** | Syslog lines containing `sshd`, `pam_unix`, `Failed password`, `Accepted` | Timestamp, Hostname, Username, Source IP (IPv4/IPv6 `::1`), Port |
| **Pipe-Delimited Auth Log** | Single-line records formatted as: `timestamp \| event \| user \| ip \| status` | Timestamp, Event Type, Username, Source IP, Status (SUCCESS/FAILED) |

## 🛡️ Security Detection Rules

### SEC-RUL-001: Brute-Force Authentication Attack
- **Objective:** Detect repeated authentication failures originating from a single source IP.
- **Default Threshold:** $\ge 5$ failed attempts from the same IP (configurable via sidebar: 1–20).
- **Severity:** `HIGH`
- **Risk Score:** `70 / 100`
- **Output:** Detailed trigger explanation including IP, attempt count, and threshold.

### SEC-RUL-002: Multiple-Account Credential Spraying
- **Objective:** Detect a single source IP targeting multiple distinct usernames with failed credentials.
- **Default Threshold:** $\ge 3$ distinct usernames failed from the same IP (configurable via sidebar: 2–15).
- **Severity:** `MEDIUM`
- **Risk Score:** `50 / 100`
- **Output:** Detailed trigger explanation including IP and targeted account names.

## 📊 Professional SOC Dashboard Features

1. **KPI Cards:**
   - Total Events Analyzed
   - Failed Logins (Rejections)
   - Successful Logins (Authorized)
   - Security Alerts (Rule triggers)
   - High-Risk Alerts
   - Unique Source IP Addresses
   - Files Analyzed
   - Parsing Success Rate ($\frac{\text{Parsed Events}}{\text{Parsed Events} + \text{Unrecognized Lines}} \times 100\%$)

2. **Authentication Activity Timeline:**
   - Dual spline area chart comparing successful (Emerald `#22C55E`) vs failed (Crimson `#EF4444`) logins over time.

3. **Alert Severity Distribution:**
   - High-contrast donut chart displaying High, Medium, and Low risk distributions, or a clean state indicator when zero threats exist.

4. **Attack Type Breakdown:**
   - Horizontal bar chart tracking detection rule frequency.

5. **Top Suspicious Source IPs:**
   - Hostile source addresses ranked by total failed authentication volume with target account annotations.

6. **Authentication Outcomes Ratio:**
   - Radial donut chart depicting percentage failure rate.

7. **SOC Threat Posture Gauge:**
   - Repaired Plotly indicator radial gauge with documented, deterministic scoring ($0$ to $100$) based on alert counts and failure ratios.

8. **Searchable & Filterable Alert Center:**
   - Interactive table and card views with real-time filtering by Severity, Alert Type, IP address, and Target Username.
   - Separate active session alerts and persistent SQLite database history.
   - One-click CSV export of filtered security alerts.

9. **7-Stage Visible Analysis Workflow:**
   - Configurable Pacing: Presentation / Demo Mode (10–12s smooth progression) vs Normal Mode (immediate processing).
   - Real computation occurring at each step with complete failure handling.

## ⚠️ System Limitations

- **Upload-Based Analysis:** Analyzes uploaded static log files; does not operate as a kernel-level packet sniffer or live syslog daemon listener.
- **Absence of Time Windows:** Rules evaluate total failures across the uploaded file scope; time-window sliding buckets (e.g. 5 fails in 60 seconds) are planned for future versions.
- **Offline Environment:** IP reputation enrichment via VirusTotal/AbuseIPDB is intentionally excluded to guarantee 100% offline readiness.
- **Log Source Scope:** Optimized for Windows Security Events, Linux SSH Syslog, and standard Auth logs. Web server access logs (Apache/Nginx CLF) require custom field mapping.

## 🌐 Deployment Guide

### Deploying to Streamlit Community Cloud
1. Push repository to GitHub (ensure `.gitignore` excludes `venv/` and `.env`).
2. Log in to [Streamlit Community Cloud](https://share.streamlit.io).
3. Select **New app**, point to repository branch `main`, and specify:
   - **Main file path:** `src/app.py`
4. Streamlit will install dependencies from `requirements.txt` and launch the app.
5. *Note on SQLite Persistence:* Cloud container restarts re-initialize local SQLite storage. For permanent cloud persistence across container lifecycles, configure external PostgreSQL or Cloud SQL.

### Offline Deployment
1. Download wheel dependencies while connected:
   ```bash
   pip download -r requirements.txt -d ./wheels
   ```
2. Transfer project folder to air-gapped machine.
3. Install wheels locally:
   ```bash
   pip install --no-index --find-links=./wheels -r requirements.txt
   ```
4. Run locally:
   ```bash
   python -m streamlit run src/app.py
   ```
